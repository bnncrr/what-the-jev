# Jev 是什么

Jev 是 TypeSafe 的决策模型，也是其首个「System One」模型。它读取自然语言但不生成文本：给定 state 和带类型的 questions，返回带校准概率的类型化答案，代码可直接据此分支。模型 ID 为 `typesafe/jev-1.13`，浮动别名 `~typesafe/jev-latest`。

## 是决策模型，不是对话模型

| | 对话 LLM | Jev |
| --- | --- | --- |
| 输入 | messages | `state` + `questions` |
| 输出 | 生成的 token | 每个问题一个类型化答案 |
| 形态 | 解析文本并校验 | 必然是你给出的选项之一，或一个概率 |
| 不确定性 | 隐含在措辞中 | 数值化，逐答案给出 |
| 模态 | 文本、图像、音频、视频 | 仅文本 |

两者都读自然语言，区别全在输出侧。需要的答案能落在枚举、布尔或数字上时用 Jev；输出本身就是文字时用 LLM。实际使用中两者配合：Jev 负责路由与校验，LLM 负责组织语言。

## 三种回答方式

三种问题类型，可在一次请求中混用。

| `type` | 提问 | 答案字段 |
| --- | --- | --- |
| `noul` | 该条件是否成立？ | `noul` — 为「是」的概率，取值 [0, 1] |
| `choice` | 是这些选项中的哪一个？ | `choice`、`probabilities`、`confidence` |
| `score` | 落在这个有序量表的什么位置？ | `score`、`legend`、`probabilities`、`confidence` |

- `noul` 是伯努利判断。概率本身就是答案，没有独立的 confidence 字段。
- `choice` 在最多 255 个具名选项中选一个。
- `score` 把 state 放到 2–10 级的有序量表上（由低到高）。`score` 是各级索引的概率加权均值，因此可能落在两级之间（三级量表上的 1.99 表示几乎落在最后一级）。

同一请求中的所有问题并行评估同一个 state，彼此看不到对方的答案。答案不会超出你给出的选项或等级。

## 能力边界

Jev 不做文本生成、不提供可见推理（没有理由说明，也没有思维链）、不做工具调用、不参与对话、不规划多步任务、不处理图像/音频/视频、不做精确算术与日期计算、不做确定性逻辑。这些留在你自己的代码或 LLM 里。

答案不会超出你的 schema，但仍可能是错的。校准的含义是：在许多同类答案上，报告的 0.8 约有 80% 正确——单个答案仍可能落在那 20% 里。

## 成本与容量

| 项目 | 值 |
| --- | --- |
| 计费 | 仅输入 token，输出 token 免费 |
| 价格 | 每百万输入 token 0.042 美元 |
| 单次费用 | 见响应中的 `usage.cost` |
| 上下文 | `state` 加最长问题合计 32,000 token |
| 输入类型 | 字符串、JSON 对象、数组 |
| 权重 | 闭源，未公开权重与论文 |

一次三问题的工单调用约 450 输入 token，花费约 0.00002 美元。

## 适用场景

擅长：路由与分流、大规模分类与打标、用 `noul` 阈值把关 Agent 的工具调用、按策略校验 LLM 输出、按分数排序与过滤、作为 LLM 评审。

不擅长：输出是散文的任务、需要算术或日期的任务、本应由数据库查询或正则完成的任务。
