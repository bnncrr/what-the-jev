# Jev 怎么用

## 流程

1. 构造 `state`：待判断的材料，可以是字符串、对象或数组。
2. 提出原子问题，每个问题带类型和定义全部答案的判定标准。
3. 发送一次请求，所有问题针对同一 state 并行作答。
4. 在自己的代码里按返回的数值分支。

## 根据任务选择回答方式

| 判断 | 回答方式 |
| --- | --- |
| 是/否事实 | `noul` |
| 一组中恰好一个 | `choice` |
| 可能同时命中多个标签 | 每个标签一个 `noul` |
| 有序程度（严重性、匹配度、优先级） | `score` |

`score` 不存在「中等」。`noul` 取 0.5 也不表示「中等」，而是「是」与「否」概率相当。

## 问题设计

- 一个问题只承载一个判断。多因素判断拆成多个问题，在代码里按权重合并，这样调整优先级是改系数而不是改提示词。
- 判定标准写成可指认的情形，而不是程度：「功能损坏但存在绕过办法」，而不是「中等严重」。
- `choice` 选项要有对比性：说明每个选项包含什么、排除什么，并补一个 `other` 兜住信息不足的情况。
- `score` 的每一级都要独立成立。Jev 逐级判断，看不到级别索引和相邻级别。一个 score 问题只衡量一个维度。
- 不要写提示词。人设、长前言和示例属于文本生成模型；Jev 需要的是 state、一个原子问题，以及每个答案的精确说明。
- 精确计算留在代码里。日期、计数、查表和算术都不是判断。
- 只发送问题需要的 state 字段；无关内容会降低准确率。
- state 是数据不是指令。state 里的文字会影响答案，因此要在 `instructions` 中说明输入是被判断的对象，而不是要执行的指令。

## 一次问全

把可能需要的问题都放进同一次请求，包括只在某个分支才用的问题（在问题里写明前提），让代码忽略用不到的答案。只有当第二个请求的 state 或选项依赖第一个答案时，才拆成两次。

## 读取答案

- `noul` 取值 [0, 1]，是「是」的概率。接近 0.5 表示确实无法判断——把它当作第三种结果，升级处理或再次提问。
- `choice` 给出被选中的选项，`probabilities` 给出各候选之间的比较，`confidence` 表示该分布的集中程度。
- `score` 是概率加权位置，索引 0 对应 criteria 中列出的第一项。`legend` 把索引映射回判定标准文本。score 不是任何比例的份额：1.0 可能表示全部权重在第 1 级，也可能表示权重各半落在第 0 级与第 2 级。
- `confidence` 描述的是候选答案的分布，不表示答案是否正确。
- 概率在多次调用之间会波动。按名称而非顺序读取 `probabilities`，并按区间而不是精确值比较。

## 阈值

用自己任务的几百条标注样本调阈值，不要用整数拍板。常见形态是三段：高于上界自动执行，中间区间标记复核，低于下界转人工。上下界应按各类错误的代价确定——自动执行出错的代价通常高于人工复核。
