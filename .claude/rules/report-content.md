# 报告内容

`experiments/<name>/report/` 下每份报告写什么，依本文件。本文件管内容，不管版式。

## 读者与目的

读者不是该领域专家，也不看单样本。他要回答一个问题：JEV 在这个场景所代表的领域里，能力如何。

报告只回答两问：

1. 这个实验在什么场景下做的。
2. JEV 在这个场景里能力如何、代价多少。

类比 benchmark：看分数与分类分数，不看单题的执行轨迹，不看模型输出的每个 token。

因此报告的粒度是分组、分布、比例、总量；只对单个样本成立的观察不进报告。

## 判断规则

1. 粒度：是否回答「这个领域的能力如何」。只对单个样本成立的不写。
2. 归属：是否落在「场景」或「能力与代价」之内。都不是的不写。
3. 行动：读者能否据此判断分数可不可信、能不能迁移、要不要复现。不能的不写。
4. 结果化：数字只写结果值本身，不写得到它的算式；成本只写消耗量与总费用。
5. 对象化：写处理后的对象，不写处理过程。只写实验所用的样本，不写原有总量与剔除数量。
6. 行为：模型一侧只写答了什么（选择、概率、对错），不写为什么这么答。
7. 无套话：每次实验都会雷同出现的话不写。

## 报告结构

顶层章节固定，不增删；小节按「结果一章的组成」取用。

```
标题
摘要
1 场景
2 结果
3 结论
参考文献
附录          可选
```

| 章 | 必须回答 |
| --- | --- |
| 摘要 | 在什么场景下、用多少样本、测得什么结果、得出什么判断。一段 |
| 1 场景 | 实验在什么条件下进行：样本从哪来、有多少、由什么构成、覆盖哪些维度、维度如何划分。章节标题用该次场景的名称，数据集类实验即「数据集」。这一章是读者判断分数含义的依据 |
| 2 结果 | 在这个场景下模型表现如何、代价多少 |
| 3 结论 | 由此对该领域能力得出什么判断。一段，解读集中在此 |
| 附录 | 放不进正文的聚合表。没有就不设 |

场景一章中，凡由本次分析补充的维度划分，必须声明它不是样本的原始标签。

## 结果一章的组成

必写：

- 整体结果：样本量、总体指标，必要时给区间；给基线或随机水平的参照值。
- 判据声明：一句说明判据来源，如「以数据集提供的标准答案为判据」。不写判据的实现。
- 调用成本：输入 token、输出 token、总费用。

按需取用，采集到才写：

| 元素 | 取用条件 |
| --- | --- |
| 分组结果 | 样本带可分的维度 |
| 指标与另一测量量的关系 | 除对错外还采集了第二变量 |
| 行为统计 | 有可聚合的行为数据 |

同一章内依次为：整体结果、分组结果、指标与另一测量量的关系、行为统计、调用成本。

## 不应写

- 模型是什么：架构、能力描述、字段含义。
- 如何调用：端点、并发、重试、prompt、请求结构、脚本、参数。
- 如何判分：比较哪些字段、选项如何落到答案字母的机制。
- 数据准备：原始总量、剔除标准与被剔样本、清理脚本。
- 单样本记录：编号、单样本的答案与模型选择、逐样本的差异说明。
- 推算与单价：算式、单价、换算过程、每样本均值。
- 维度划分的细则规则。
- 局限一节，以及「未作重复采样」「不能推广到其他场景」这类话。
- 自我声明与免责。
- 造词与非日常表达。
- 只复述响应、不给判断的句子。

## 用词

规范正文用通用词，报告按该次实验的对象命名：样本即题目，输入即材料与设问，指标即准确率，维度即历史阶段，第二测量量即所选概率。

## 交付前自检

逐条回答，任一为「是」则重写。

- 有内容只对单个样本成立？
- 有内容在讲模型实现、调用方式或判分方式？
- 有数字给了算式、单价或推算过程？
- 有句子只在复述响应，没有给出判断？
- 有每次实验都会雷同出现的套话？
- 有自我声明、免责，或造词？
- 场景一章缺了「维度划分由本次分析补充」的声明？
- 结构里增删了顶层章节，或漏了必写项？
